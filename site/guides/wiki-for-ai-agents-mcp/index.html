Which wikis work with AI agents through MCP?

We build Turtle, so this guide is not neutral. We checked competitor claims on vendor pages on 27 November 2026. MCP support changes fast, so check the sources before you decide.

Short answer

Five of the six wikis here have an MCP server from the vendor: Turtle, Confluence Cloud, Notion, Outline and Docmost. BookStack has community servers only. The real differences are in the details: who the agent acts as, whether you can limit it to reading, and whether MCP is part of the free or self-hosted build.

What MCP is, and why a wiki is a natural target

The Model Context Protocol (MCP) is an open standard that lets an AI client such as Claude call tools in another app. The app runs an MCP server. The client connects to it, signs in, and gets a list of actions it may take, such as search, read a page or create a page.

A wiki is a natural target because it holds the text agents need and produce. An agent can read your runbooks before it answers an on-call question. It can also write the docs you keep postponing. That makes your wiki a knowledge base for AI agents and a place where they leave their work.

What to look for in a wiki MCP server

Seven questions separate one wiki MCP server from another.

  • Who does the agent act as? The safest model is an agent that acts as the person who connected it, with that person's permissions and nothing more.
  • Can you limit its permissions? Look for a way to give the agent less than you have, not only the same.
  • Are changes attributed? When an agent edits a page, the history should show both the person and the agent.
  • Is there a read-only scope? Many teams start with an agent that can only search and read.
  • Is there an admin kill switch? An admin should be able to turn off AI connections for the whole workspace in one place.
  • Is MCP in the free build or a paid tier? Some vendors gate MCP behind a licence, credits or a plan.
  • Official or community server? A community server can work well, but you run it, update it and trust its code yourself.

How each wiki handles MCP

Turtle

Licence: AGPL-3.0, no paid edition.

Turtle has a built-in MCP server at <your address>/mcp. Clients connect with OAuth, and an agent never gets more access than the member who connected it. You can limit it to reading or to single Areas, and admins can switch AI connections off for the workspace. Gaps: no per-page permissions, groups or SSO yet, and the API can change before 1.0.

Confluence

Licence: proprietary, cloud subscription.

The Atlassian Rovo MCP server is official and cloud hosted. Atlassian says actions respect the user's existing permissions. Admins control access through domain settings, IP allowlists and an API token switch. Connecting is free, but enriched calls consume Rovo credits, and Free plans get no monthly credit allowance. We found no Data Center option. If you need a Confluence MCP alternative you can host yourself, that is the main gap.

Notion

Licence: proprietary, cloud only.

Notion runs an official hosted MCP server and says it works on every plan, including Free. The agent reads and updates what you can access in the selected workspace. Some features, such as MCP tokens and connected-source search, need Business or Enterprise. The older open-source local server is no longer actively maintained. There is no self-hosted Notion.

Outline

Licence: BSL 1.1 (source available, not OSI open source).

Outline added a built-in MCP server in February 2026 and expanded it in April 2026. It works on cloud and self-hosted installs at /mcp, with OAuth by default or an API key. An admin can turn MCP off for all members in the workspace AI settings. The docs do not describe read-only scopes or how agent edits are attributed.

Docmost

Licence: AGPL-3.0 core, with enterprise code under a separate Docmost licence.

Docmost ships its own MCP server at /mcp, but it needs a Business or Enterprise licence. With OAuth, the app acts as you and can never do more than your account. The authorization screen lets you switch off Write, which limits the agent to read tools. API keys are not limited this way, but an admin can enforce OAuth.

BookStack

Licence: MIT.

We found no official MCP server on BookStack's site. Several community projects wrap the BookStack API. One we checked uses a BookStack API token, offers 21 read tools and 22 write tools, and keeps writes off by default. You run and maintain such a server yourself.

How to connect Claude to Turtle

You can try this on the public demo at demo.turtle-wiki.app. It needs no sign-up and resets every six hours.

  1. In Turtle, open the menu at the foot of the sidebar, where your name is shown, and choose Connect AI.
  2. Copy Turtle's MCP address. It is your Turtle address followed by /mcp.
  3. In Claude, open Settings, then Connectors, and choose Add custom connector.
  4. Name it Turtle, paste the address and choose Add.
  5. Choose Connect next to Turtle. Turtle opens in your browser.
  6. Sign in to Turtle if it asks, choose what Claude may do under Limit access, then choose Allow.

From now on, Claude works with your access and never more. When it edits a page, the change shows as your name plus "via Claude", for example "Demo Member via Claude".

Prompts to try on the demo

The demo has an Area called Acme Engineering with a Runbooks folder, an on-call handbook and a Decisions folder. Try these:

  • "Summarise the Runbooks in the Acme Engineering Area."
  • "Read 'Rolling back a release' and list the steps as a checklist."
  • "Compare the on-call handbook with 'Deploying to production' and point out gaps."
  • "Draft a new page in Decisions that records today's choice, using the existing decision page as a model."

Every write by the agent is a version you can restore.

Tokens instead of OAuth

Some clients and scripts cannot sign in through a browser. For those, create a manual token. A token can be read-only, limited to certain Areas and set to expire. The same token also works for Turtle's HTTP API.

Risks and governance

An agent with write access can change many pages quickly.

  • Start read-only. Give the first connection read access, or a read-only token, and widen it later.
  • Limit the blast radius. Restrict the agent to the Areas it needs. In Turtle this is the finest level today, since per-page permissions are still on the roadmap.
  • Keep attribution on. Pick a wiki that records agent edits under the person who connected it, so reviews and audits stay possible.
  • Know your kill switch. Find out where an admin turns off AI connections before you need it. In Turtle, workspace admins can do this for the whole workspace.
  • Watch for prompt injection. A page can contain text that tries to steer the agent. Review agent edits on sensitive pages before you rely on them.
  • Check maturity. Turtle is in an early phase, without an external security review before 1.0.

How to choose

If you already live in Atlassian Cloud and pay for Standard or higher, the Rovo MCP server is the simple path. If your team is in Notion, its hosted server works on every plan. If you self-host and want MCP without a licence fee, Outline and Turtle both ship it in the self-hosted build. Docmost does too, but only with a Business or Enterprise licence. With BookStack you will run a community server.

Pick Turtle if you want an open-source, self-hosted wiki where agents act as the member, read-only and Area limits are built in, and edits show who and which agent. Pick something else if you need per-page permissions, SSO or groups today.

Frequently asked

What is a wiki MCP server?

It is a service that lets AI clients such as Claude search, read and write wiki pages through the Model Context Protocol. The wiki decides which actions exist and which permissions apply.

Does Confluence Data Center have an MCP server?

We found no Atlassian MCP server for Data Center. Atlassian's Rovo MCP server documentation covers Cloud only, as of 27 November 2026.

Can an AI agent see pages I cannot see?

Not in Turtle. An agent never has more access than the member who connected it. Atlassian, Notion and Docmost describe the same rule for their servers.

Can I make the agent read-only?

In Turtle, yes, through the connection or a read-only token. Docmost offers it for OAuth connections. We found no read-only scope in the Outline or Atlassian MCP docs.

Do I need Claude to use Turtle's MCP server?

No. Claude is one MCP client. Any client that supports MCP with OAuth can connect, and tokens cover clients that cannot sign in.

Is MCP part of a paid Turtle plan?

No. Turtle has no paid edition, and every feature is in the AGPL-3.0 repository. A hosted version is announced, but it has no price or date yet.
