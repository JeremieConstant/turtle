# Security policy

## Reporting a vulnerability

Report a vulnerability privately through GitHub: open the repository's **Security** tab and choose **Report a vulnerability**. Only you and the maintainers see it.

Never report a vulnerability in a public issue, pull request or discussion. That tells everyone how to attack Turtle before a fix exists.

A good report says:

- which release of Turtle you found it in
- what an attacker can do with it, and what they need first (to be a Member, a Role, a link)
- the steps to reproduce it

## Supported releases

While Turtle is below 1.0, only the latest release gets security fixes. A fix comes as a new release; upgrade to it.

## What happens after a report

1. A maintainer confirms that the report arrived within seven days.
2. We reproduce the problem and tell you whether we consider it a vulnerability, and how serious.
3. We fix it privately and publish a release with the fix. You hear before the release goes out.
4. Once the release is out, we publish a security advisory that describes the problem and names you, unless you would rather not be named.

Please keep the vulnerability to yourself until the advisory is published.
