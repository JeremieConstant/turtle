# Turtle is its own OAuth authorization server

Connectors in claude.ai and Claude Desktop sign in with OAuth and cannot send a fixed `Authorization` header, so a Member could only connect Claude by copying a Token into a tool that has no place for it. Turtle therefore implements the MCP authorization specification itself: OAuth 2.1 with PKCE, protected resource and authorization server metadata, and open Dynamic Client Registration, all built into the binary like the MCP endpoint (ADR-0005). An external identity provider such as Keycloak or Entra was rejected because it would add a second service to run and configure for every installation; single sign-on can later become a way to sign in to Turtle without changing who issues the Tokens.

A connection made through OAuth is a Token of the Member who allowed it, an Agent acting for that Member, so there is still one kind of credential and the rule that a Token never has more access than its owner holds unchanged. OAuth needs a fixed issuer address, which Turtle cannot safely take from the `Host` header behind a proxy, so it is only offered when `TURTLE_PUBLIC_URL` is set. Turtle never calls out to find out whether it is reachable from the internet.
